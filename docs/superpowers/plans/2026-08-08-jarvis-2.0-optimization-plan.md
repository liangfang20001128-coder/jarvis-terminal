# 贾维斯 2.0 优化总方案

日期：2026-08-08
来源：三份并行审计报告合并（安全+逻辑 / 效率+重复 / UI交互+设计）+ 用户交互反馈
审计报告：
- docs/audits/2026-08-08-security-logic-audit.md（P0×1、P1×4、P2×12、P3×6）
- docs/audits/2026-08-08-duplication-data-audit.md（模块评分与数据/效率问题）
- docs/audits/2026-08-08-ui-ux-audit.md（交互一致性 + 设计美观）

## 0. 结论

项目架构清晰、数据真实、无已提交密钥。2.0 的三大主线：**安全收口（P0/P1）→ 逻辑与数据修复（P1/P2）→ 交互与设计重构（含用户反馈的排版诉求）**，最后做 2.0 新功能增强并回归部署。

## 1. 交互与排版（用户诉求优先）

1. **默认恢复轨道式自由排布**：不再默认把模块拉到左上角 3×3 网格；各模块回到自然位置（媒体左、热点右、时运右下、天气底部中央），验证无重叠；「自动排版」降级为可选的对齐视图。
2. **统一窗口控件（macOS 一套交通灯）**：删除展开层右上 ✕ 与左下「深入」按钮；✕=收起展开层、−=最小化到状态栏、⚲=展开/深入（二三层切换）。
3. **状态栏区分**：最小化胶囊改为玻璃拟态 + 实时状态 + tooltip；模块 chips 保持切换语义。
4. **语义统一**：点击空白只收起展开层；基础态 ✕ 不再静默最小化。
5. **可访问性**：交通灯改 button + aria-label；触屏提示补全。

## 2. 安全收口（P0 → P1）

1. 本机服务默认绑定 127.0.0.1（云端仍 0.0.0.0）；CORS 改为 Origin 白名单（本机仅 localhost 页面）。
2. 写接口（/api/chat、/api/divine、/api/open、/api/launch）加本地令牌校验（config.js 注入 `X-Jarvis-Token`）+ 简单限流（内存令牌桶，本机环回放宽）。
3. openTarget：type 白名单枚举（app/file/reveal）；路径用 path.resolve + realpath 边界校验；app 分支统一走 JARVIS_LAUNCH 白名单并预置常用应用（抖音/哔哩哔哩/QQ音乐等）。
4. POST body 上限 1MB + 请求超时；runCodex 临时文件用后即删（0600）；runChatAPI 加 60s AbortController 超时；respCache LRU（上限 100）+ 响应体大小上限。
5. Host 白名单校验（127.0.0.1/localhost）；本机忽略 X-Forwarded-For；API 补安全响应头。
6. 前端移除 inline onclick（data 属性 + 事件委托），esc 补引号转义。

## 3. 逻辑与数据修复（P1/P2）

1. **前端缓存 TTL 化**：热点 3 分钟 / B站 5 分钟 / 模型目录 6 小时，超时静默刷新；删除空转 interval。
2. **影音提示反转修复**：本机显示「一键启动桌面版（白名单已预置）」、云端显示「打开网页版」；/api/status 返回可启动列表。
3. **聊天加载态**：「思考中」气泡 + 30s 超时提示 + 失败重试一次。
4. **搜索防抖 300ms + AbortController**；**滚动统计节流 500ms**。
5. **页面可见性**：document.hidden 时暂停非关键轮询，恢复后立即补刷；**首屏懒加载**（模块展开才拉数据）。
6. **SYSTEM_PROMPT 模块白名单补 weather**；天气降级链完整（current/daily 任一缺失即降级）；前后端 WMO 映射统一为单一来源（后端下发）。
7. **并行抓取**：getHot/getBiliHot/getAi 改 Promise.allSettled，首条成功即返回。
8. **Token 真实用量**：DeepSeek 响应 usage 回传，按通道分别统计（本地 Codex 不计费）。

## 4. 架构与功能重复清理

1. 删除旧 drawer/deep 死代码与重复的 openLayer/closeLayer 定义（统一为一套）。
2. 删除死接口 /api/github/activity；/api/workspace 与 /api/repo/tree 明确职责（本机文件 vs 云端仓库）。
3. 应用启动统一走白名单通道（openTarget app 复用 launchApp）。
4. 行为统计合并为单一按日聚合 store（含导出），消除 recordUse/__anal/__track/tokens 四套碎片。
5. refreshOpen 改局部更新（避免输入框失焦/滚动重置）；每日运势 localStorage 键做 7 天滚动清理。

## 5. 2.0 新功能增强

1. **/api/health**：数据源健康度（最近成功时间 / fallback 状态），前端状态栏显示健康徽标。
2. **影音**：公开曲库搜索（Internet Archive）+ 电台多台切换（SomaFM 频道列表）；明示「个人账号仅支持跳转打开」边界。
3. **空间（云端）**：接入 GitHub 仓库搜索（按文件名/README 检索）。
4. **行为洞察**：每日建议生成（结合时运宜忌输出「今日专注建议」）。
5. **AI 模块**：展示服务端真实 token 用量与成本（按通道）。
6. **时运**：运势分标注「娱乐参考」；玄学顾问回答增加免责说明（安全审计联动）。

## 6. 实施顺序与验证

1. **阶段 A 安全收口**（P0/P1）：绑定环回 + Origin 白名单 + 令牌 + 限流 + 路径校验 + 启动统一白名单 + 临时文件/超时/LRU。
2. **阶段 B 逻辑修复**：缓存 TTL、影音提示、聊天加载态、防抖/节流、可见性暂停、懒加载、并行抓取、SYSTEM_PROMPT、token 真实用量。
3. **阶段 C 交互/设计重构**：轨道式默认排布、统一交通灯、状态栏区分、语义统一、可访问性、设计 token 收敛。
4. **阶段 D 新功能 + 部署**：/api/health、影音曲库/电台、云端搜索、每日建议、真实 token；本地回归 → 推送 → 线上验证（接口 + 浏览器全模块走查）。

每阶段独立提交并在本地验证后推送；最终线上回归覆盖：安全头/鉴权、热点与天气新鲜度、聊天加载态、窗口交互、默认排版无重叠。
