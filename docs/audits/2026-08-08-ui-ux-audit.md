# 贾维斯 2.0 审计报告：UI 交互逻辑 + 设计美观性

审计日期：2026-08-08
审计范围：web/index.html（3064 行）交互代码与样式（.fp / .win-bar / .mini-dock / .h-dock / .h-cmd / openLayer / closeLayer / miniLayer / restoreMini / setAuto）
审计维度：交互逻辑一致性、macOS 交互语义、排版策略、视觉设计统一性、可访问性
严重度：P1=高优先，P2=改进项，P3=打磨项

> 说明：本维度原由并行审计智能体负责，该智能体在浏览器实测阶段卡住，已由主智能体接管完成本报告（交互代码为本项目当前实现，主智能体具备完整上下文）。

## 一、执行摘要

macOS 窗口化交互（常驻交通灯 + 最小化到状态栏）方向正确且已可用，但存在三处结构性体验问题：

1. **一个窗口三套操作控件**（交通灯 ✕/−/⚲ + 右上 ✕ + 左下「深入」）并存，语义重叠、入口混乱——这是「按钮挤在最上角」观感的直接来源（与效率审计 P2-4 一致）。
2. **默认自动排版把 8 个模块排成从左上角开始的 3×3 网格**，与「环绕地球的轨道式自由排布」设计意图冲突（用户反馈「不用都拉到最上角」）。
3. **状态栏双轨制**：h-dock 模块 chips 与 mini-dock 最小化胶囊并存，视觉区分不足，用户难以分辨「聚焦切换」与「最小化还原」。

## 二、交互逻辑一致性发现

### P1-1 展开窗口内三套操作控件并存
位置：web/index.html 交通灯注入（.win-bar, 约 1440-1470）、exp-close（1521/1652）、exp-more（1520/1653）
问题：展开后同时存在「交通灯 ✕/−/⚲」「右上 ✕」「左下 ◈ 深入」三个操作入口；✕ 在交通灯与右上重复，缩小按钮在交通灯存在。视觉上所有按钮挤在窗口角落，违背 macOS「一套交通灯」的简洁语义。
建议：统一为交通灯一套控件——✕=收起/还原、−=最小化、⚲=展开/深入（在二三层间切换）；删除 exp-close 与 exp-more，保留「深入」进入第三层的通道到 ⚲ 的二次点击或内容底部按钮。

### P1-2 默认排版策略与设计意图冲突
位置：web/index.html setAuto 默认开启（约 3050-3060）
问题：默认把 8 个模块按优先级排成从左上角开始的 3×3 网格，丢失「媒体在左、热点在右、时运在右下」的轨道式构图，也与用户明确反馈的「不用都拉到最上角」相悖。
建议：默认恢复轨道式自由排布（每模块自然位置，天气补位底部中央，验证无重叠）；「自动排版」降级为可选视图；或在自动排版时采用「环绕中央地球的环形/轨道布局」而非左上角网格。

### P2-3 点击空白收起与交通灯 ✕ 语义不一致
位置：holo click 空白关闭（1726-1732）vs wb-close（基础态=最小化）
问题：空白点击只收起展开层；交通灯 ✕ 在基础态会直接最小化。同一「关闭」语义两种行为，易误触。
建议：统一语义——✕ 仅负责「收起/还原展开层」，最小化只由 − 触发；基础态 ✕ 无操作（或与 − 一致并在 tooltip 说明）。

### P2-4 状态栏双轨制（chips vs 胶囊）视觉区分不足
位置：.h-dock .chip（226-236）vs .md-pill（mini-dock）
问题：底部同时存在「模块切换 chips」与「最小化胶囊」，两者都是圆角小条，仅图标/文字不同；用户不知道点哪个是切换、哪个是还原。
建议：胶囊改为「图标 + 实时状态 + 红点」样式，使用与 chips 不同的底色/边框/阴影，并加 tooltip（如「点击还原 天气」）；chips 保持纯切换语义。

### P3-5 键盘与触屏可达性
位置：.wb 为 <i> 元素（无 tabindex/aria）；拖动依赖 pointer/hover
问题：交通灯不可键盘操作；drag-hint/expand-hint 依赖 hover，触屏设备无提示。
建议：交通灯改 <button aria-label="最小化">；为触屏加点击展开提示（已有「点击展开 ▸」），迷你胶囊可长按拖动排序。

## 三、设计美观性发现

### P2-1 内容区大量内联样式，与设计 token 体系脱节
位置：DETAIL/DEEP/MINI 渲染函数（约 2320-2760）
问题：大量 `style="..."`（rgba 硬编码、font-size 10/11px 零散取值）绕过全局 CSS 变量与类体系，未来调主题色/字号需逐处改。
建议：收敛为设计 token 类（.dw-sub/.d-line/.d-chip 等），内联样式仅保留动态值（宽度百分比）。

### P2-2 字号与层级不统一
位置：.lab 9px / 正文 10-11px / 迷你胶囊 10px / .fate-time 22-24px
问题：层级靠字号微弱区分，卡片标题与内容对比不足。
建议：定义 4 级字号阶梯（标题 13px/模块标题 9-10px/正文 11px/辅助 9px），标题加字距与 accent 色。

### P3-3 迷你胶囊与窗口卡片风格不一致
位置：.md-pill（flat 半透明）vs .fp（玻璃拟态 + 高光描边）
问题：胶囊偏「按钮」，与全息玻璃窗口不是一个视觉家族。
建议：胶囊复用玻璃拟态（backdrop blur + 1px 高光描边 + 呼吸光晕），仅尺寸缩小。

### P3-4 展开内容与交通灯可能重叠
位置：.fp.expanded padding-top 34px（新加）与 DETAIL 内容首行
问题：34px 留白对多数内容够用，但第三层长内容滚动时交通灯悬浮于内容之上属预期（macOS 亦然）；需确认滚动条与交通灯不互相遮挡。
建议：滚动条改细样式并让出右侧 8px；交通灯 hover 时加深背景以保证可读性。

## 四、2.0 UI/UX 优化建议

1. **统一窗口控件**：删除 exp-close/exp-more，交互收敛为交通灯一套（✕ 收起 / − 最小化 / ⚲ 展开-深入切换）。
2. **默认轨道式排布**：恢复自然位置（天气底部中央），自动排版改为可选「对齐网格」视图，不再默认拉左上角。
3. **状态栏区分**：最小化胶囊玻璃化 + 实时状态 + tooltip；chips 保持切换语义。
4. **统一语义**：✕ 只收起展开层；最小化只由 − 触发；点击空白只收起展开层。
5. **设计 token 收敛**：内联样式替换为类体系，定义统一字号阶梯与玻璃拟态规范。
6. **可访问性**：交通灯改按钮 + aria-label；触屏提示；胶囊支持键盘还原。
7. **动画稳定**：展开/收起用 transform + opacity 过渡，避免 innerHTML 重建引发的闪烁；数据刷新局部更新（配合效率审计 P3-1）。
